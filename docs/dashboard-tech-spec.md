# Marketing Performance Dashboard — Tech Spec

Версия: v1 (draft)
Источник данных: `datank.xlsx` (см. [`data-dictionary.md`](./data-dictionary.md))
UX-flow: см. [`ux-flow.md`](./ux-flow.md)

## 1. Цель и scope

### 1.1 Бизнес-цель
Дать менеджеру, маркетологу и руководителю единое окно для быстрого анализа трафика, конверсий и результативности рекламных кампаний по периодам, продуктам и каналам. Дашборд должен сокращать время на ответ на вопросы вида:
- «Какой продукт принёс больше всего НК в марте?»
- «Какие кампании в Директе самые эффективные по AR онлайн?»
- «Где просели визиты по сравнению с прошлым месяцем?»

### 1.2 Пользовательские роли

| Роль                         | Что делает на дашборде                                                                                  |
|------------------------------|---------------------------------------------------------------------------------------------------------|
| Маркетолог                   | Анализ источников трафика, кампаний, метрик CTR / CR / AR.                                              |
| Руководитель                 | Просмотр KPI верхнего уровня, динамики по месяцам, лидеров и аутсайдеров.                              |
| Аналитик                     | Проверка качества данных, фильтрация, экспорт, сравнение периодов.                                      |
| Контент / продукт-менеджер   | Анализ эффективности страниц/продуктов и сравнение онлайн vs офлайн воронки.                            |

### 1.3 Входит в scope v1
- Веб-дашборд в репозитории GitHub с deploy preview (Vercel или статический хостинг).
- Загрузка Excel-файлов (`.xlsx`, `.xls`), парсинг, валидация, preview.
- Семь разделов: Overview, Traffic, Conversions, Campaigns, Products / Pages, Data Quality, Uploads.
- 12 KPI-карточек, 8 типов визуализаций, фильтры с сохранением в URL и пресетами.
- Экспорт графиков в PNG/SVG, таблицы — в CSV.
- Compare mode: текущий период vs предыдущий период.

### 1.4 Не входит в scope v1
- Полноценный ETL в DWH.
- Авторизация и разграничение по ролям через SSO.
- Автоматическая интеграция с рекламными кабинетами через API.
- Мобильное приложение (только адаптив на desktop-first).
- Прогнозирование, ML-рекомендации.

## 2. Функциональные требования

### 2.1 Структура экрана
- Верхняя панель — фильтры (sticky).
- Левая навигация — переход между разделами (sidebar 240–280 px).
- Центральная область — KPI-карточки и графики.
- Нижний блок — таблица детализации с экспортом.

### 2.2 Разделы навигации

| Раздел           | Содержимое                                                                              |
|------------------|-----------------------------------------------------------------------------------------|
| Overview         | Все 12 KPI + динамика по месяцам + воронка + delta vs предыдущий месяц.                 |
| Traffic          | Показы, клики, CTR, визиты. Линейные графики, top-N кампаний по визитам.                |
| Conversions      | Заявки онлайн/офлайн, CR, НК, AR. Stacked bar по продуктам, воронка.                    |
| Campaigns        | Эффективность кампаний: horizontal bar (top по визитам / CR / AR), таблица с фильтром.  |
| Products / Pages | Сравнение продуктов: grouped bar по визитам и заявкам, heatmap продукт × источник.      |
| Data Quality     | Пропуски, нетипичные значения, дубликаты, ошибки импорта.                               |
| Uploads          | Загрузка нового Excel, история версий, активный файл.                                   |

### 2.3 KPI-карточки (Overview)
Показы, Клики, CTR, Визиты, Заявки онлайн, Заявки офлайн, CR онлайн, CR офлайн, НК онлайн, НК офлайн, AR онлайн, AR офлайн.

Каждая карточка показывает: текущее значение, дельту к предыдущему периоду (абсолютную и %), мини-спарклайн.

### 2.4 Фильтры (обязательные)
- **Период**: один месяц, мультивыбор месяцев, compare mode (выбор двух периодов).
- **Страница / продукт** (мультивыбор).
- **Источник трафика** (мультивыбор).
- **Название рекламной кампании** (мультивыбор + поиск).
- **Тип метрики**: все / онлайн / офлайн.
- Кнопка **Reset all**.
- **Сохранённые пресеты фильтров** (имя пресета хранится в `localStorage`).

### 2.5 Логика фильтрации
- Все графики и таблицы обновляются синхронно при изменении любого фильтра.
- При выборе нескольких месяцев — суммарное значение + динамика по месяцам.
- При выборе одного продукта — все KPI пересчитываются только по нему.
- При пустом результате — empty state, **не ошибка**.
- Состояние всех фильтров сериализуется в URL query params (`?months=Январь,Февраль&product=PDL%20онлайн&...`) для шаринга.

### 2.6 Визуализации (обязательные)

| Тип графика          | Что показывает                                                          |
|----------------------|-------------------------------------------------------------------------|
| Линейный график      | Визиты, заявки, НК по месяцам.                                          |
| Grouped bar          | Сравнение продуктов / страниц по визитам и заявкам.                     |
| Stacked bar          | Онлайн vs офлайн заявки по продуктам.                                   |
| Horizontal bar       | Топ кампаний по визитам, CR, AR.                                        |
| Funnel               | Показы → клики → визиты → заявки → НК.                                  |
| Heatmap              | Продукт × источник трафика по CR или AR.                                |
| Detail table         | Сортировка, поиск, экспорт CSV.                                         |
| Delta cards          | Изменение к предыдущему месяцу.                                         |

Все графики имеют tooltip, legend и кнопку экспорта в PNG/SVG.

### 2.7 Логика расчётов
Производные метрики **пересчитываются на клиенте** после фильтрации; формулы и обработка деления на ноль описаны в [`data-dictionary.md`](./data-dictionary.md), §4. Запрещено усреднять CTR/CR/AR между строками — сначала суммируем абсолютные значения, затем считаем долю.

### 2.8 Пустые состояния и UX
- Файл не загружен → onboarding с кнопкой «Загрузить Excel».
- Фильтры дали пустой результат → плашка «Нет данных по выбранным условиям».
- Колонка отсутствует → понятное сообщение со списком отсутствующих колонок.
- Неверные типы данных → список ошибок импорта в Data Quality.

## 3. Нефункциональные требования

|-----------------|-----------------------------------------------------------------------------------|
| Производительность | Первая загрузка дашборда < 3 c на типовом ноутбуке для файла до 10 000 строк.  |
| Адаптивность    | Desktop-first, минимальная ширина рабочей области 1280 px.                         |

### 4.3 Модель данных

```ts
type DashboardRow = {
  month: string
  product: string
  trafficSource: string
  campaignName: string
  impressions: number
  clicks: number
  ctr: number
  visits: number
  onlineLeads: number
  offlineLeads: number
  crOnline: number
  crOffline: number
  nkOnline: number
  nkOffline: number
  arOnline: number
  arOffline: number
}
```

Дополнительно к каждой строке прикладывается служебное поле:

```ts
type RowMeta = {
  isAggregate: boolean   // строка "Итого ..."
  isMissing: Partial<Record<keyof DashboardRow, boolean>>
  warnings: string[]     // soft-валидации
}
```

### 4.4 Поток загрузки Excel
1. Drag-and-drop или кнопка **Upload Excel**.
2. Поддержка `.xlsx` и `.xls`.
3. Если в файле несколько листов — пользователь выбирает лист (по умолчанию `datank`).
4. Preview первых 20 строк.
5. Mapping колонок согласно §2 [`data-dictionary.md`](./data-dictionary.md).
6. Нормализация (числа, проценты, пустые значения, строки `Итого`).
7. Валидация через Zod; ошибки структуры → блокируют загрузку, soft-warnings → попадают в Data Quality.
8. Последняя версия сохраняется в `localStorage` (как ArrayBuffer + parsed JSON) с ограничением размера.
9. Поддерживается замена файла без перезагрузки приложения и история последних N (например, 5) загрузок.

### 4.5 Параметры окна
- Sidebar 240–280 px, контент скроллится отдельно.
- Верхняя панель фильтров sticky (`position: sticky; top: 0`).
- KPI-блок: 1 ряд на ≥ 1440 px, 2 ряда на 1280–1440 px.
- Все интерактивные элементы — с состояниями hover / active / disabled / focus.

### 4.6 Тестирование

| Уровень       | Что покрываем                                                                  |
|---------------|--------------------------------------------------------------------------------|
| Unit (Vitest) | `parser.ts`, `metrics.ts`, `validators.ts`, `query-state.ts`, `formatters.ts`. |
| Component (RTL) | KPI-карточки, фильтры, таблица, рендер графиков (мок-данные).               |
| E2E (Playwright) | Загрузка `datank.xlsx`, применение фильтров, проверка URL, экспорт CSV/PNG. |

Smoke-датасет — текущий `datank.xlsx` (3 месяца, 5 продуктов, 2 источника, 88 строк).

### 4.7 Мониторинг и логирование (v1)
- Клиентская телеметрия: ошибки импорта, время рендера, размер загруженного файла (без содержимого).
- Sentry или аналог — опционально, поведенчески выкл. по умолчанию.

## 5. Acceptance criteria

1. Дашборд открывается менее чем за 3 секунды на типовом ноутбуке с локальным файлом до 10 000 строк.
2. После загрузки корректного Excel пользователь видит KPI, графики и таблицу без ручной настройки.
3. Все фильтры влияют на все графики и таблицы синхронно.
4. URL сохраняет состояние фильтров (открытие ссылки восстанавливает дашборд в том же виде).
5. Пользователь может загрузить новый Excel без пересборки проекта.
6. При ошибочной структуре файла система показывает список отсутствующих колонок.
7. Все графики имеют tooltip, legend и экспорт в PNG/SVG.
8. Таблица поддерживает сортировку, поиск и экспорт в CSV.
9. Есть пустые состояния, состояния загрузки и сообщения об ошибках.
10. На GitHub есть `README.md` с инструкцией запуска, описанием структуры данных и примером файла.

## 6. Этапы реализации

1. **Data dictionary + smoke-датасет.** Зафиксировать `data-dictionary.md` по `datank.xlsx`. (готово в этой итерации)
2. **Parser + validation layer.** SheetJS → нормализация → Zod-валидация. Покрыть unit-тестами.
3. **Layout, navigation, filters.** Sidebar, верхняя панель, синхронизация с URL.
4. **KPI cards + 4 базовых графика.** Overview-экран.
5. **Upload, preview, error handling.** Полный поток Uploads + Data Quality.
6. **Detail table, экспорт CSV/PNG, compare mode.** Закрытие acceptance criteria.

## 7. Риски и допущения

| Риск                                                          | Митигация                                                                       |
|---------------------------------------------------------------|---------------------------------------------------------------------------------|
| Структура Excel меняется (переименование колонок).            | Mapping вынесен в `config/columns.ts`; импортер показывает список отсутствующих колонок. |
| Большие файлы (> 50 000 строк) тормозят клиентский рендер.    | Виртуализация таблицы, агрегация на воркере, ограничение v1 — 10 000 строк.     |
| Неконсистентные написания продуктов (`PDL онлайн` vs `PDL Онлайн`). | Не нормализуем по `lowercase`; в Data Quality показываем «похожие» категории. |
| Разные форматы процентов в разных файлах.                     | Правила нормализации в §3 `data-dictionary.md`, покрытые unit-тестами.          |
