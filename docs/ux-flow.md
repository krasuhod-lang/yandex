# UX Flow — Marketing Performance Dashboard

Документ описывает пользовательские сценарии, навигацию между экранами, состояния интерфейса и логику взаимодействия с фильтрами и графиками. Сопровождает [`dashboard-tech-spec.md`](./dashboard-tech-spec.md).

## 1. Карта экранов

```
            ┌───────────────────────────────────────────────────────┐
            │                  Top filter bar (sticky)              │
            ├──────────┬────────────────────────────────────────────┤
            │          │                                            │
            │ Sidebar  │   Main content (per section)               │
            │          │                                            │
            │ Overview │   ┌─────────────┐  ┌───────────────────┐   │
            │ Traffic  │   │ KPI cards   │  │ Charts            │   │
            │ Convers. │   └─────────────┘  └───────────────────┘   │
            │ Campaigns│                                            │
            │ Products │   ┌──────────────────────────────────────┐ │
            │ Data Q.  │   │  Detail table + CSV export           │ │
            │ Uploads  │   └──────────────────────────────────────┘ │
            └──────────┴────────────────────────────────────────────┘
```

- Sidebar — 240–280 px, ширина не меняется при скролле.
- Top bar — sticky, всегда виден.
- Main content — единственная скроллируемая область.

## 2. Onboarding (первый вход)

1. Пользователь открывает приложение, активного файла нет.
2. На центральном экране показывается onboarding-карточка:
   - Иконка-плейсхолдер.
   - Заголовок «Загрузите Excel, чтобы увидеть дашборд».
   - Кнопка **Загрузить Excel** (открывает диалог выбора файла) + drop-зона.
   - Ссылка «Скачать пример файла» → `datank.xlsx`.
   - Свернутый блок «Какие колонки нужны» → раскрывает список из data-dictionary.
3. Sidebar и фильтры **отключены** (disabled), пока нет данных.
4. После успешной загрузки — переход в раздел **Overview**, фильтры активируются, URL заполняется query-параметрами по умолчанию.

## 3. Базовый сценарий «Анализ месяца»

> Роль: руководитель. Цель: понять, как прошёл март относительно февраля.

1. На Top bar выбирает фильтр **Период → Март (21.03)**.
2. Включает **Compare mode → Февраль**.
3. На **Overview** видит:
   - 12 KPI-карточек с текущим значением, дельтой и спарклайном.
   - Линейный график (визиты / заявки / НК) с двумя сериями: Март и Февраль.
   - Funnel: показы → клики → визиты → заявки → НК.
4. Кликает на KPI «AR онлайн» — раскрывается секция с топ-кампаниями по AR онлайн (переход в **Campaigns** с предзаполненной сортировкой).
5. Делает экспорт линейного графика в PNG для отчёта.

## 4. Сценарий «Сравнение продуктов»

> Роль: контент-менеджер. Цель: сравнить эффективность продуктов.

1. Переходит в раздел **Products / Pages**.
2. Выбирает все продукты (мультиселект по умолчанию пустой = все).
3. Фильтр **Тип метрики → онлайн**.
4. Видит:
   - Grouped bar: визиты vs онлайн-заявки по продуктам.
   - Stacked bar: онлайн vs офлайн заявки по продуктам.
   - Heatmap продукт × источник по `crOnline`.
5. Сохраняет текущий набор фильтров как пресет «Продукты — онлайн».

## 5. Сценарий «Качество данных»

> Роль: аналитик. Цель: проверить только что загруженный файл.

1. После загрузки нового файла приложение автоматически подсвечивает в sidebar бейдж с количеством warnings у раздела **Data Quality**.
2. В разделе видны:
   - Список отсутствующих обязательных колонок (если есть) — блокирующие ошибки.
   - Таблица soft-warnings: дубликаты ключей, `visits < onlineLeads + offlineLeads`, выпадающие проценты вне `[0, 1]`, строки `Итого`.
   - Кнопка «Скачать список ошибок» (CSV).
3. Аналитик решает: продолжить работу или загрузить новый файл (раздел **Uploads**).

## 6. Сценарий «Загрузка нового файла»

1. Раздел **Uploads** → кнопка **Upload Excel** или drag-and-drop.
2. Если в файле > 1 листа — модалка **Выбор листа** со списком листов и количеством строк. По умолчанию выделен лист `datank` (если есть).
3. **Preview**: первые 20 строк после нормализации, видно как Excel-заголовки сматчились на канонические поля. Если соответствие не найдено для обязательной колонки — preview подсвечивает её красным.
4. Кнопка **Применить** активна только при отсутствии блокирующих ошибок.
5. После применения старый файл сохраняется в истории (последние 5), активным становится новый. Все открытые экраны автоматически перерисовываются.

## 7. Состояния интерфейса

| Состояние                | Где                       | Что показываем                                                              |
|--------------------------|---------------------------|------------------------------------------------------------------------------|
| Empty (нет файла)        | Любой раздел кроме Uploads| Onboarding-карточка с CTA «Загрузить Excel».                                |
| Loading (парсинг файла)  | Uploads + контент-зона    | Скелетоны KPI/графиков, прогресс-индикатор парсинга.                         |
| Empty по фильтрам        | Любой график/таблица      | Плашка «Нет данных по выбранным условиям» + кнопка **Сбросить фильтры**.    |
| Ошибка структуры файла   | Uploads                   | Красный alert со списком отсутствующих колонок и ссылкой на data-dictionary.|
| Ошибка типов данных      | Data Quality              | Список ошибок с указанием строки/колонки, кнопка экспорта.                  |
| Деление на ноль          | KPI, таблица              | Значение `—`. В tooltip — пояснение «Нет визитов / показов / заявок».        |

## 8. Логика URL и пресетов

- Каждое изменение фильтра обновляет query-параметры через `replaceState` (без перезагрузки).
- Поддерживаемые ключи: `section`, `months`, `products`, `sources`, `campaigns`, `metricType`, `compareWith`, `search`.
- Список значений сериализуется через запятую с URL-encode.
- Пресеты хранятся в `localStorage` (`presets:v1`) как `{ name, query }`. Применение пресета — это просто `pushState` нужного query.
- Кнопка **Reset all** очищает фильтры и query-параметры (остаётся только `section`).

## 9. Доступность и состояния элементов

- Все интерактивные элементы — с состояниями `default / hover / active / focus-visible / disabled`.
- Фокус-кольцо видимо при навигации с клавиатуры.
- Все графики имеют **легенду** и **tooltip**, доступные с клавиатуры (по фокусу на серию).
- Цветовая палитра подобрана с контрастом не ниже WCAG AA для текста и легенд.
- Heatmap дополнительно показывает значения числом, а не только цветом, чтобы не зависеть от различения цветов.

## 10. Микровзаимодействия

- При наведении на KPI-карточку — слабая тень и стрелка-индикатор «Перейти в раздел».
- При клике на сегмент funnel/bar — фильтр расширяется выбранной категорией (с подтверждением через тост «Фильтр добавлен», с кнопкой «Отменить»).
- При экспорте — короткий toast «PNG скачан» / «CSV скачан».
- При смене файла — баннер «Активный файл: <имя>, загружен <дата>» в верхней части контента.
