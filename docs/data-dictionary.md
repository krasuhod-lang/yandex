# Data Dictionary — `datank.xlsx`

Документ описывает структуру входного Excel-файла, который является основным источником данных для Marketing Performance Dashboard (v1).

## 1. Общая информация о файле

| Параметр                  | Значение                                                |
|---------------------------|---------------------------------------------------------|
| Имя файла                 | `datank.xlsx`                                           |
| Формат                    | Excel Open XML (`.xlsx`), также поддерживается `.xls`   |
| Кодировка строк           | UTF-8                                                   |
| Лист с данными            | `datank` (единственный лист в текущей версии источника) |
| Заголовок                 | строка 1 (русскоязычные названия колонок)               |
| Кол-во колонок            | 16                                                      |
| Кол-во строк данных       | 88 (без заголовка)                                      |
| Технические строки "Итого"| 10 (отмечаются по полю `Название рекламной кампании`)   |

Парсер должен:
1. Принимать имя листа параметром (по умолчанию — `datank`).
2. Считать первой строкой заголовки и приводить их к каноническим именам через mapping.
3. Не падать, если в файле есть лишние пустые колонки/строки.

## 2. Канонические поля и mapping колонок

| № | Заголовок в Excel              | Каноническое поле     | Тип        | Единицы     | Обязательность | Примечание                                                                 |
|---|--------------------------------|-----------------------|------------|-------------|----------------|----------------------------------------------------------------------------|
| 1 | `Месяц`                        | `month`               | string     | —           | да             | Свободная строка, например `Январь`, `Февраль`, `Март (21.03)`             |
| 2 | `Страница/продукт`             | `product`             | string     | —           | да             | Категория продукта/посадочной страницы                                     |
| 3 | `Источник трафика`             | `trafficSource`       | string     | —           | да             | Канал привлечения, например `Директ`, `SEO`                                |
| 4 | `Название рекламной кампании`  | `campaignName`        | string     | —           | да             | Может быть `-` для строк без кампании и `Итого ...` для агрегатов          |
| 5 | `Показы`                       | `impressions`         | number     | шт.         | да*            | Может быть пусто/`-` для каналов без показов (например, SEO)               |
| 6 | `Клики`                        | `clicks`              | number     | шт.         | да*            | См. примечание про `-` ниже                                                |
| 7 | `CTR`                          | `ctr`                 | number     | доля 0..1   | нет            | В Excel хранится как доля (например `0.099` = 9.9%). Пересчитывается, если пусто |
| 8 | `Визиты`                       | `visits`              | number     | шт.         | да             | Сессии на сайте                                                            |
| 9 | `Заявки онлайн-выдача`         | `onlineLeads`         | number     | шт.         | да             |                                                                            |
| 10| `Заявки офлайн-выдача`         | `offlineLeads`        | number     | шт.         | да             |                                                                            |
| 11| `CR онлайн`                    | `crOnline`            | number     | доля 0..1   | нет            | Если пусто/0 — пересчитать как `onlineLeads / visits`                      |
| 12| `CR офлайн`                    | `crOffline`           | number     | доля 0..1   | нет            | Если пусто/0 — пересчитать как `offlineLeads / visits`                     |
| 13| `НК онлайн`                    | `nkOnline`            | number     | шт.         | да             | НК = «новый клиент» / выдача                                               |
| 14| `НК офлайн`                    | `nkOffline`           | number     | шт.         | да             |                                                                            |
| 15| `AR онлайн`                    | `arOnline`            | number     | доля 0..1   | нет            | Если пусто/0 — пересчитать как `nkOnline / onlineLeads`                    |
| 16| `AR офлайн`                    | `arOffline`           | number     | доля 0..1   | нет            | Если пусто/0 — пересчитать как `nkOffline / offlineLeads`                  |

\* «обязательно» означает, что колонка должна присутствовать в файле. Конкретное значение в ячейке может быть пустым или равным `-`; правила нормализации описаны ниже.

## 3. Нормализация значений

Парсер обязан применять следующие правила:

1. **Пустые ячейки и `-`, `—`, `n/a`, `N/A`, `null`** → `null` для строк, `0` для счётных метрик с явным указанием `isMissing=true` в служебном поле строки. UI показывает такие значения как `—`.
2. **Числа в текстовом виде** (например `"1 550"` с неразрывным пробелом, `"1,234.56"`, `"1.234,56"`) — приводятся к `number`. Поддерживаются разделители `,` и `.` для дробной части, пробелы и `\u00A0` как разделители тысяч.
3. **Проценты**:
   - Если ячейка имеет числовой формат `%` — значение хранится как доля (Excel сам делит на 100). Используем как есть.
   - Если ячейка строка вида `"9,9%"` — парсим в `0.099`.
   - Если ячейка число без формата `%` и значение `> 1` — считаем, что это «9.9» вместо «0.099», и делим на 100.
4. **Строки `Итого ...`** в колонке `campaignName` помечаются флагом `isAggregate=true` и **исключаются из расчёта KPI** (чтобы не было двойного учёта). Они доступны в режиме «показать агрегаты» в таблице детализации.
5. **Дубликаты** (одинаковая комбинация `month + product + trafficSource + campaignName`) подсвечиваются в Data Quality, но не блокируют загрузку.
6. **Деление на ноль** при пересчёте производных метрик возвращает `null`; UI отображает `—`.

## 4. Производные метрики

Все производные метрики **пересчитываются на клиенте** после применения фильтров и агрегации:

| Метрика     | Формула                              | Условие                                    |
|-------------|--------------------------------------|--------------------------------------------|
| `ctr`       | `clicks / impressions`               | если поле пустое или `impressions = 0` → `—` |
| `crOnline`  | `onlineLeads / visits`               | если `visits = 0` → `—`                    |
| `crOffline` | `offlineLeads / visits`              | если `visits = 0` → `—`                    |
| `arOnline`  | `nkOnline / onlineLeads`             | если `onlineLeads = 0` → `—`               |
| `arOffline` | `nkOffline / offlineLeads`           | если `offlineLeads = 0` → `—`              |

При агрегации по группе сначала суммируются абсолютные показатели (`impressions`, `clicks`, `visits`, `onlineLeads`, `offlineLeads`, `nkOnline`, `nkOffline`), а **затем** считаются производные. Усреднять CTR/CR/AR между строками **запрещено**.

## 5. Уникальные значения в текущем файле

Используются для smoke-тестов парсера и e2e-тестов фильтров.

- `Месяц`: `Январь`, `Февраль`, `Март (21.03)` — 3 значения.
- `Страница/продукт`: `PDL онлайн`, `PDL Офлайн`, `Долгосрочный`, `Кредитная линия`, `Пенсионный` — 5 значений. **Внимание:** `PDL онлайн` и `PDL Офлайн` различаются регистром второго слова — нормализатор не должен схлопывать их по `lowercase`.
- `Источник трафика`: `Директ`, `SEO` — 2 значения. Для `SEO` поля `Показы`, `Клики`, `CTR` обычно содержат `-`.
- `Название рекламной кампании`: ~80 уникальных значений + 10 строк вида `Итого ...`.

## 6. Валидация при импорте (Zod-схема, концептуально)

Импортер проверяет:

1. Наличие всех 16 колонок-заголовков из таблицы § 2. Если отсутствует хотя бы одна обязательная колонка — импорт прерывается, пользователю показывается список **отсутствующих** колонок.
2. Тип данных в каждой колонке после нормализации (`number` для метрик, `string` для категорий).
3. `month`, `product`, `trafficSource` не пустые ни в одной строке данных — иначе строка попадает в Data Quality.
4. `visits >= onlineLeads + offlineLeads` (мягкая проверка, warning).
5. `nkOnline <= onlineLeads`, `nkOffline <= offlineLeads` (мягкая проверка, warning).
6. CTR/CR/AR (если переданы из файла) лежат в диапазоне `[0, 1]` после нормализации; иначе — warning.

## 7. Расширения формата (на будущее, не v1)

- Колонка `date` (точная дата) для дневной грануляции.
- Колонка `region` для региональной аналитики.
- Колонка `cost` / `revenue` для расчёта CPC, CPL, ROMI.
- Поддержка нескольких листов (`datank_pdl`, `datank_long`, …) с автоматическим объединением.
