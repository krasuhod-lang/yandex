# Выручай.ру — операционный дашборд

Статический демо-дашборд для управленческого просмотра экономики роста, JTBD, AI/SOS, партнёров, retention и unit-экономики.

## Актуальная структура репозитория (пути относительно корня репозитория)

- `./index.html` — точка входа для хостинга: автоматически перенаправляет на `vyruchai-mediaplan.html` (большинство статических хостингов открывают `index.html` по корневому адресу)
- `./vyruchai-mediaplan.html` — основной HTML-файл интерфейса
- `./cjm-unit-dashboard.js` — единственный активный SPA-слой «CJM & Юнит-экономика Выручай.ру»: сегменты, CJM, юнит-экономика, сводная матрица и вкладка «Финмодель 2027» (Бюджет → Прогноз продаж → Ожидаемая прибыль). Поддерживает «Скопировать ссылку»: текущее состояние (сегменты, ручные вводы, доли, финмодель) сжимается (LZString) и кодируется в короткий `location.hash` (`#z=`), и любой пользователь, открывший ссылку, увидит те же цифры.
- `./chart-lib.js` — самодостаточный canvas-рендерер (глобальный класс `Chart`), выделенный из бывшего `dashboard-app.js` для нужд `cjm-unit-dashboard.js`.
- `./dashboard-app.js`, `./unit-economics-lab.js`, `./economics-model.js` — устаревший «старая версия»-слой; больше не подключается из `vyruchai-mediaplan.html` и оставлен в репозитории только для истории.
- `./data/pnl-baseline.json` — распарсенный baseline PNL (smoke-сверка модели против факта)
- `./data/seo-stages.json` — офлайн-материал по SEO-плану (на дашборде не используется)
- `./tools/parse-pnl.py`, `./tools/parse-seo-plan.py` — offline-парсеры xlsx → JSON (`pip install --user openpyxl`)
- `./PNL - Выручай.ру.xlsx` — исходный Excel-срез для demo-контекста
- `./Новая таблица (1).xlsx` — дополнительный Excel-файл в репозитории, вспомогательный материал для сравнения данных
- `./Раунд 2 - Выручай сэнсэй с деньгами будет всё окей.pptx` — вспомогательная презентация; для запуска дашборда не нужна

## Что реализовано сейчас

- единый слой фильтров по роли, каналу и сценарию;
- контур данных с явным статусом источника, режима и полноты среза;
- пресеты сценариев, reset и индикатор несохранённых изменений для модели;
- role-aware приоритеты и рекомендации вместо чисто статических подсказок;
- расширенный drill-down для KPI, сценариев, партнёров, сигналов и экспериментов;
- улучшенная доступность drawer: фокус, клавиатурная навигация, закрытие по `Esc`;
- цветовое выделение ключевых строк PnL (выручка, расходы, прибыль, рентабельность) и отдельная строка чистой маржи;
- увеличенный зазор между легендой и областью графика, чтобы подписи рядов не наезжали на сам график;
- блок аргументации разбивки JTBD по процентам (спрос → воронка → выручка) с декомпозицией долей;
- блок-схема маршрутизации трафика (раздел «CJM») в формате диаграммы со стрелками между блоками, как в Miro: два входных потока → идентификация → S2S API ЦФ (POST /api/v1/cf/check-hash) → ветвление по статусу клиента → витрины офферов; SVG-воронка + HTML-сетка из 6 мини-карточек на ветку (без обрезки текста);
- эпик «Smart Safe Router · CJM-маршрутизация»: 4 user story по ТЗ (Soft Reject, LTV Recovery, Anti-Cannibalization, NPL Monetization), полная Decision Tree матрица из 8 статусов (CF_TARGET / CF_ACTIVE / CF_REPEAT / CF_DORMANT / CF_OVERDUE / CF_REJECTED / CF_NON_CORE / NOT_FOUND) с явно перечисленными разрешёнными и заблокированными категориями офферов, 4 интерфейсных 3-шаговых сценария (включая NPL Monetization → БФЛ + HR), Zero-Waste KPI-блок, калькулятор ёмкости.
- фокусный одностраничный дашборд «CJM & Юнит-экономика Выручай.ру» по новому ТЗ: 5 вкладок (обзор сегментов, CJM, юнит-экономика, SSR, окупаемость/микс), глобальный фильтр по 4 сегментам, As-Is / To-Be симуляция и localStorage для пользовательских вводов.
- вкладка «Финмодель 2027» (новая версия): единый план «Бюджет → Прогноз продаж → Ожидаемая прибыль» до декабря 2027. Воронка считается от источников трафика через оставленные номера и CPL, база Центрофинанс работает как трекер лида, продажа лида обратно в Центрофинанс по 3000 ₽ убрана из выручки. Все параметры (экспонента выручки, замедление после мая 2027, линейный рост расходов, доля SEO-эффекта для платных каналов, бюджеты/CPL по каналам, конверсии, доли 5 сегментов, партнёрские ставки за выдачу, ФОТ, разработка, цель 12,5 млн ₽/мес) редактируются вручную, сохраняются локально и при наличии same-origin backend API `/api/cjm-state` синхронизируются в общую базу для других пользователей. Дефолтный сценарий откалиброван по PNL: расходы растут не экспоненциально, а выручка ускоряется за счёт накопительного SEO/бренд-эффекта.

## Как читать модель (стрелки между разделами)

`economics-model.js` собирает дерево показателей сверху вниз и отдаёт его дашборду через `window.EconomicsModel.build(inputs, base)`. Любое изменение допущения на «Обзоре» инвалидирует кэш модели и перерисовывает все 8 табов:

- **Обзор** ← `model.pnl` + `model.kpis` (payback вычисляется, а не хардкодится);
- **Трафик** → отдаёт визиты/CPC в модель ↔ ← EPC считается из выручки модели (`epc=revenue/offerClicks`);
- **Воронки** → отдают CR на каждом шаге, в модели появляется «утечка выручки» по шагам;
- **JTBD** → доли служат весами для аллокации трафика по продуктовым линиям;
- **AI/SOS** → корректирует `router.matchRate` и `router.pApprovalStep2/3`;
- **CJM (Smart Safe Router)** → центральный узел, считает `revenue_router`, `blended_CAC`, `ltv_lift`; payouts читаются из `routerPayout2/3` (Proxy `DYNAMIC_PAYOUTS`);
- **Повторные продажи** → `crm.repeatRate12m`, `marginRepeat`, `churnMonthly` → LTV каналов;
- **Юнит-экономика** → краткая витрина модели: 4 ветки CJM с долей, выручкой на пользователя и вкладом, плюс стоимость лида, средняя выручка на лид, маржа на лид и окупаемость рекламы.

**Сценарии:** на «Обзоре» доступны 3 пресета из `EconomicsModel.PRESETS` — `conservative`, `base`, `marketplace_mature`. На пресете «маркетплейс зрелый» юнит-экономика выходит в плюс за счёт match-rate ~55%, repeat-rate ~35%, кросс-карты ~18%, tier-бонуса +12%.

**Валидаторы:** все вводные сверяются с коридорами правдоподобности (`EconomicsModel.CORRIDORS` — PDL CR 18–35%, repeat 25–55%, match 40–70%, tier ≤ 25%). Нарушения подсвечивают поле красным и выводят список в панели «Валидаторы».

**Экспорт/Импорт сценария:** кнопки на «Обзоре» сохраняют/загружают `modelInputs + seoStages` как JSON.

**Smoke-сверка:** при загрузке дашборд сравнивает `model.pnl` с `data/pnl-baseline.json` и пишет в консоль `console.warn`, если месячная дельта по выручке превышает 5%.

## Как открыть локально

Так как в репозитории нет сборки и `package.json`, достаточно отдать файлы как статику.

### Вариант 1: Python HTTP server

```bash
python3 -m http.server 8000
```

После этого откройте:

- `http://localhost:8000/vyruchai-mediaplan.html`

### Вариант 2: любой статический хостинг

Нужны только файлы:

- `index.html` (точка входа, делает редирект)
- `vyruchai-mediaplan.html`
- `cjm-unit-dashboard.js`
- `chart-lib.js`

После загрузки на хостинг откроется корневой адрес сайта (`/`), который автоматически перенаправит на дашборд. Раньше при заливке без `index.html` хостинг отдавал 404/пустую страницу по корневому адресу — теперь это исправлено.

### Поделиться ссылкой с текущими данными

В шапке дашборда есть кнопка «Скопировать ссылку». Она упаковывает все ручные правки (сегменты, доли, финмодель) в хвост URL после `#z=` — состояние предварительно сжимается (LZString), поэтому ссылка получается заметно короче (обычно в ~2–3 раза меньше прежнего формата) и её удобно скопировать и отправить в мессенджере. Ссылка кладётся в буфер обмена, адресная строка обновляется, а любой пользователь, которому вы отправите адрес, откроет дашборд ровно с теми же цифрами и показателями — сервер и авторизация для этого не нужны, всё работает как обычная статика. Старые ссылки формата `#s=` (base64) по-прежнему открываются.

## Ограничения текущей версии

- данные пока встроены в JS как demo-срез, без полноценного runtime-импорта Excel;
- графики рисуются встроенным canvas-классом `Chart`, а не внешней библиотекой;
- проект не содержит отдельных automated build/test scripts.

## Следующий логичный шаг

Если развивать продукт дальше, следующий этап — вынести demo-данные в отдельный data-layer файл и добавить реальную загрузку пользовательского Excel/JSON-среза без переписывания UI.
